## Issues (ranked)
**1. Ready rule passes a thesis made only of zero-width spaces** (wrong logic)
- Where: `wlReady` (index.html ~7152). Repro: Watchlist item with `my_thesis.why` and `.exit` = `"​"` → `wlReady()` is true, so a plan can open with an effectively blank thesis. Also true for other non-`trim()` blanks (NBSP is trimmed; ZWSP/BOM/word-joiner are not).
- Cause: uses `String.trim()` only. (`data_checks.py`)

**2. `BRK.B` and `BRK-B` are different symbol keys** (wrong logic)
- Where: `wlSymKey` (~4961) only strips `.BK`. Repro: `wlSymKey('BRK.B')='BRK.B'`, `wlSymKey('BRK-B')='BRK-B'` → the same stock can sit in Watchlist and Candidates (or twice in Watchlist) under both spellings. Not checked: whether every add path normalises `-`/`.` beforehand. (`PTT`/`PTT.BK`/`ptt.bk` collapse correctly.)

**3. Idea import accepts non-string `name`; saved and shown as `[object Object]`** (wrong data, verified)
- Where: `ideaParse` (~14993). Repro: idea@1 with `"name": {"a":1}` → check passes, save succeeds, UI shows `[object Object]` (no console error). `name=[1,2]` saved as array too.
- Cause: `String(o.name).trim()` is validated but the original value is stored (`idea[k]=o[k]`).

**4. Idea / Living-thesis importers accept many wrong-typed fields** (wrong data, mostly unverified)
- Fuzz: idea 154 and lt 113 single-field type swaps pass the check (e.g. `id=12345`, `sym=[...]`/`{}`, `name=null` for lt). Many are harmless string coercions; only #3 was traced to bad stored data. UI save+re-render with `chain=null`, `segments=[null,5,"x"]`, `bullets=[null]` did not throw. Worth a schema type check (type-check stored value, not the coerced one). (`bughunt-fuzz.txt`)

**5. Backup-restore parse and Playbook validator accept null in some fields** (low)
- `bkRestoreParse` accepts `_meta.uid`, `_meta.activeAccount`, `_meta.accounts` = null (restore then names accounts by id; not run through a real restore since that writes). `Calc.pbValidate` accepts `doc_url=null`. Both only affect labels/links as far as read.

**6. Layout @390: `<small>` "% ของถัง Momentum" reported extending past viewport** (layout, unconfirmed by eye)
- Where: `.sumGrid.sumG3 > .sumCell.sumNw > small`. Flagged by `crawl_all.py` after a click on every tab at 390 only; its rect is 0 at first load (hidden until the summary section opens). Not measured how far it overflows or whether the page scrolls (page-level overflow check = 0).

**7. Test regression p64 (new vs named known list)** (tests)
- `run_tests_phase64.py:93` `page.locator('[data-tq-f="pass"]').click()` times out (30 s) — reproduced 3× solo, so not load flakiness. PL2-report says p64 was green after its last fix, so something later (PL2b/c or the copy-only commit) likely removed/renamed that filter chip or hides it. Not investigated further.
