## 1. ตำแหน่งในระบบ

```
ข่าว / สิ่งที่สังเกต
  → skill idea-scout (แทน idea-to-industry) โหมด scan → JSON idea@1 → 📥 Import → Watch › Ideas
  → ผู้ใช้เลือกส่วนของ value chain → idea-scout โหมด pick (แปะ JSON เดิม) → 📥 Import
  → แท็บ "บริษัท" → → Watchlist + คัดลอก Handoff → living-thesis (lite)
```

- หน้า Watch: `[Watchlist] [Ideas] [Candidates]` · Ideas สำหรับหุ้น Core เท่านั้น (Sat = futures ไม่เกี่ยว)
- **Candidates** = บริษัทจาก Ideas (สถานะ ศึกษา/รอข้อมูล/รอตรวจ) ที่ยังไม่อยู่ Watchlist · **เลิกอ่าน collection `research` เดิม** (ตัดสิน 2026-10-04 · ข้อมูลเดิมไม่ลบ แค่ไม่อ่าน) · ตัด ticker ซ้ำ
- Firestore `users/{uid}/ideas/{id}` (subcollection ใหม่ → ต้องเพิ่ม rules)

## 3. หน้ารายการ Ideas

หัวรายการ: `＋ ไอเดีย` · `📥 Import`
- `＋ ไอเดีย` = ฟอร์มสั้น 4 ช่อง (ชื่อ · ไอเดียประโยคเดียว · โน้ตของฉัน · หุ้นที่นึกไว้) → สถานะ **ร่าง** · ไม่เรียก AI
- การ์ดสถานะร่าง: ⋯ → `คัดลอกคำสั่ง scan` (แอปประกอบคำสั่ง + โน้ตให้) → Import ผลแล้วสถานะเป็น "กำลังสำรวจ"

1 แถว: จุดสี · ชื่อ · งานที่รอ (ถ้ามี) · ตลาด · จำนวนบริษัท · ป้ายสถานะ · วันที่ (⚠ เกิน 30 วัน)
จุดสี = **ต้องทำอะไรไหม**: 🔴 สัญญาณพักชนแล้ว · 🟡 มีงาน (บริษัทพร้อมส่งต่อแต่ยังไม่อยู่ Watchlist / สัญญาณพักระดับ watch) · ⚪ รอเฉย ๆ
เรียง: แดง → เหลือง → ที่เหลือตามวันที่อัปเดต

## 4. การ์ดไอเดีย — 5 แท็บ

| แท็บ | มาจากฟอร์มส่วน | แสดงอะไร |
|---|---|---|
| สรุป | 0 + 1 + ข้อสรุป | ประโยคเดียว · อะไรเปลี่ยน · ตัวผลักดัน · ทำไมตอนนี้ · ประเภท · รู้แล้ว / ยังเป็นสมมติฐาน · พักเมื่อ · ลำดับศึกษา · ข้อสรุป (AI เสนอ) · แถบเงื่อนไข "พร้อมส่งต่อ" |
| กลไก | 2 | เส้นเหตุ-ผลขั้นบันได (ขั้นไม่แน่นอนที่สุด = ส้ม) · ใครจ่าย · ทำไมต้องจ่าย · ทางเลือกอื่น · จุดอ่อนสุด |
| หลักฐาน | 3 | ตารางหลักฐาน (ป้าย + ＋/−) · ตาราง "พักเมื่อ" (ok/watch/hit) · ข้อมูลที่ขาด (ระดับ · สถานะ · ปุ่ม 📝 ตอบ) |
| Value chain | 4 | กล่องต้นน้ำ→ปลายน้ำ · ได้/เสีย/ปนกัน · **ticker ในแต่ละกล่อง** (สีเหลือง + ? = รอตรวจจาก match · บริษัทเดียวอยู่ได้หลายกล่อง) · ⚠ กับดักรายได้เพิ่มแต่กำไรไม่เพิ่ม · ส่วนที่เลือก · Bottleneck · **กล่องแดง: หุ้นของเราที่อยู่ฝั่งเสีย** |
| บริษัท | 5 + 6 + 7 | รายการตามลำดับศึกษา · สถานะ ศึกษา/รอข้อมูล/พัก (ผู้ใช้แก้ได้) · รายละเอียด · `→ Watchlist` · `คัดลอก Handoff` (แอปประกอบข้อความเอง) |

ตัวเลขสีส้มบนแท็บ = เรื่องที่ต้องดู (สัญญาณพักขยับ / มีหุ้นของเราฝั่งเสีย)

## 5. กติกาบังคับ (structural)

1. ตั้งสถานะ **พร้อมส่งต่อ** ไม่ได้ ถ้าไม่มี: หลักฐานขัดแย้ง (−) ≥1 · สัญญาณพัก ≥1 · บริษัทสถานะ "ศึกษา" ≥1 · **และยังมีข้อที่ขาดระดับ "ต้องรู้" ที่เปิดอยู่** (ต้องตอบ หรือปิดเป็น "หาไม่ได้" พร้อมเหตุผลก่อน)
2. ปุ่ม **→ Watchlist** กดไม่ได้ ถ้าบริษัทนั้นไม่มี `relevance_src` (แหล่งยืนยันว่าเกี่ยวกับธีม) — แสดงเหตุผลข้างปุ่ม
3. สัญญาณพักระดับ `hit` → ไอเดียขึ้นจุดแดง + เสนอให้ผู้ใช้ตั้ง "พัก" (ไม่เปลี่ยนเอง)
4. Import ซ้ำ: ไม่ทับ `status` / `rank` / `state` ที่ผู้ใช้ตั้ง · `log` append

## 6. ป้ายไอเดียบนหุ้น (ได้ / เสียประโยชน์)

- skill ใส่ `losers[]` เฉพาะที่มี **ticker + เหตุผล + แหล่ง** · ฝั่งได้ = `candidates[]` สถานะ ศึกษา/รอข้อมูล
- แอปจับคู่ ticker ตอนแสดงผล (`wlSymKey`) · ไม่เก็บ field ลิงก์ในหุ้น
- **แถว = บรรทัดเดียว ห้ามตัดบรรทัด:** `TICKER · ส่วน value chain (ตัดด้วย …) · สัญลักษณ์` · ไม่มีคอลัมน์ "ที่มา"
  - สัญลักษณ์: `▲` เขียว = ได้ประโยชน์ · `▼` แดง = เสียประโยชน์ · ต่อท้าย `?` = รอตรวจ (เช่น `▲?`) · ส่วน value chain ที่ยังรอตรวจเป็นสีเหลือง + `?`
  - หลายไอเดีย = หลายสัญลักษณ์ (`▲ ▼`) · ช่องส่วน value chain เขียน "2 ไอเดีย"
  - ชื่อไอเดีย / ส่วน / สถานะ อยู่ใน tooltip (มือถือ: แตะการ์ดดู)
  - ตัวกรอง `[ ]`: ทั้งหมด · ▲ ได้ · ▼ เสีย · บรรทัด legend ตัวเล็กท้ายรายการ
- **การ์ดหุ้น:** ส่วน "ไอเดียที่เกี่ยวข้อง" = 1 แถวต่อไอเดีย `▲/▼ · ชื่อไอเดีย · ส่วน value chain ›` (แตะเปิดไอเดีย) · ฝั่งเสีย = พื้นแดงอ่อน
- ปุ่ม `📊 รายได้แยกส่วน` บนการ์ดหุ้น → เปิดหน้า TradingView `tradingview.com/symbols/{EXCHANGE}-{TICKER}/financials-segments/` (ไม่ใช้ token) · ใช้ดูคร่าว ๆ เท่านั้น · ตัวเลขที่ใช้เป็นหลักฐานยังต้องมาจากเอกสารบริษัท
- ขึ้นที่: แถว **Watchlist** · แถว **Candidates** (เรียงหุ้นที่มีป้ายขึ้นก่อน) · การ์ดหุ้นมีส่วน "ไอเดียที่เกี่ยวข้อง" (ได้/เสีย · ลำดับศึกษา · คำถามให้ Thesis · ปุ่มเปิดไอเดีย)
- ไอเดียฝั่งตัวเอง: กล่องแดงในแท็บ Value chain ถ้ามีหุ้นของเราอยู่ฝั่งเสีย
- แสดงเฉพาะไอเดียสถานะ `need_evidence` หรือ `ready` (ร่าง / กำลังสำรวจ / พัก = ยังไม่ขึ้นป้าย)
- ปุ่ม `คัดลอก Handoff (update)` → ส่งให้ living-thesis โหมด update ใช้เป็นหลักฐานฝั่ง bear · **ไอเดียไม่เปลี่ยน Thesis เอง**
- ไม่ขึ้นหน้าวันนี้ (ยกเว้นกรณีหุ้นที่ **ถืออยู่** + ไอเดีย `ready` → 1 แถวในรายการ "งาน" ครั้งเดียวจนกว่าจะรัน update)

## 6b. asset อื่น (XAU · BTC · Brent · S50) — แบบ B: บอกไว้เฉย ๆ

**หลัก: ข้อมูลประกอบ ไม่ใช่สัญญาณเทรด** · Bias / แผน Sat ยังมาจาก Weekly Bias + Macro Playbook เหมือนเดิม
- skill ใส่ `assets[]` เฉพาะเมื่อกลไกชัด · **สูงสุด 3 ตัว** · ทิศ `↑` `↓` หรือ `ผันผวน` · ป้าย Inference เสมอ · ไม่ชัด = ไม่ใส่ (ห้ามใส่เพื่อให้ครบ)
- **แสดงที่เดียว:** แท็บสรุปของการ์ดไอเดีย 1 บรรทัด `asset อื่น: [Brent ↑] [S50 –]` · แตะป้าย = เปิดการ์ด Playbook ของ asset นั้นในแท็บ Flow · เหตุผลอยู่ใน tooltip
- **ไม่แสดง:** หน้ารายการ Ideas · Watchlist · Candidates · แท็บวันนี้ · หน้า Sat
- ฝั่ง Flow: การ์ด Playbook ไม่เพิ่มอะไรบนหน้าการ์ด · ใน full report มีบรรทัดพับ "ไอเดียที่เกี่ยว (n)" ท้ายสุดเท่านั้น
- ไอเดียที่ `ready` + มี asset → ใช้เป็นข้อมูลตอนทบทวน change_if (macro-playbook-loop) ไม่เตือนอัตโนมัติ

## 7. เชื่อมแท็บวันนี้ (เฉพาะสิ่งที่ต้องลงมือ)

| ขึ้นเมื่อ | ที่ไหน | ข้อความตัวอย่าง |
|---|---|---|
| สัญญาณพักของไอเดียชน (`hit`) | ด่วน | `💡 ไฟฟ้า… สัญญาณพักชน — ทบทวนไอเดีย` |
| บริษัทสถานะ "ศึกษา" ยังไม่อยู่ Watchlist | ช่อง Stock Selection (ตลาดตรงกัน) | `ส่งต่อ VRT → Watchlist` |
| ไอเดีย "รอหลักฐาน" ถึงวันนัดตรวจ (`recheck` วันที่) หรือเกิน 30 วัน | ช่อง Stock Selection · สูงสุด 1 แถว/วัน | `เช็คหลักฐาน: GLP-1 (ยอดขายอาหาร Q3)` |
| หุ้นที่ **ถืออยู่** อยู่ฝั่ง ▼ ของไอเดีย `ready` | งาน (ครั้งเดียว จนกว่ารัน living-thesis update) | `💡 XYZ ▼ ไฟฟ้า… — update Thesis` |
| ไอเดีย "รอหลักฐาน" ปกติ | **ไม่ขึ้น** | — |
| asset อื่น · ป้าย ▲▼ · ไอเดียกำลังสำรวจ / ร่าง / พัก | **ไม่ขึ้น** | — |

- ทุกแถวจากไอเดียขึ้นต้นด้วย `💡` · บรรทัดเดียว · แตะ = ไปที่การ์ดนั้นในหน้า Watch
- รวมแถวจากไอเดีย **ไม่เกิน 2 แถว/วัน** นอกช่องด่วน (เรียง: ถืออยู่ ▼ → ส่งต่อ → เช็คหลักฐาน)

เพิ่ม field `recheck` (วันที่ + สิ่งที่รอ) ใน idea@1 เพื่อให้ "รอหลักฐาน" มีวันนัด แทนการโผล่ทุกวัน

## 8. skill `idea-scout` — 2 โหมด (+ full)

| โหมด | ทำส่วน | ใช้เมื่อ | งบ token (ประมาณ) |
|---|---|---|---|
| `scan` (default) | 1–4 + losers + recheck · ไม่ค้นหาบริษัท | ไอเดียใหม่ | ≤40k |
| `pick` | 5–6 เฉพาะส่วน value chain ที่ผู้ใช้เลือก · ต่อยอดจาก JSON scan | หลังผู้ใช้เลือกส่วน | ≤40k |
| `full` | 1–6 รอบเดียว | ผู้ใช้มั่นใจธีมแล้ว / ไอเดียเล็ก | ≤70k |
| `match` | จับคู่ list หุ้นกับไอเดีย (ดู 8b) | มี list จาก screener | ~3–5k / 50 ตัว |
| `update` | เช็คสัญญาณพัก + หลักฐานใหม่ + recheck | ถึงวันนัด / มีข่าวชน | ≤20k |

**รอบ 1 `scan`** — ส่ง: ไอเดีย 1–2 ประโยค · ที่มา · ตลาด → ได้: แท็บ สรุป · กลไก · หลักฐาน · Value chain (+ ฝั่งเสีย · วันนัดตรวจ · ส่วนที่ AI เสนอให้ดูก่อน) · แท็บบริษัทยังว่าง
→ ผู้ใช้ตัดสินในแอป: รอหลักฐาน / พัก / ติ๊กส่วน value chain ที่จะศึกษา → Export JSON
**รอบ 2 `pick`** — ส่ง: ส่วนที่เลือก + JSON รอบ 1 → เพิ่ม: บริษัท + แหล่งยืนยัน + นัยต่อทั้งบริษัท + ทำไมตัวนี้ + ไม่ได้ประโยชน์ถ้า + คำถามให้ Thesis + ลำดับ/สถานะเสนอ · ส่วน 1–4 แก้เฉพาะที่มีหลักฐานใหม่ + log 1 บรรทัด

**ไอเดียของผู้ใช้เอง** — แปะโน้ต (ไอเดีย · กลไกที่คิด · หุ้นที่นึกไว้ · ส่วนที่ไม่แน่ใจ · กรอกไม่ครบได้)
- ข้อความผู้ใช้ติดป้าย `ผู้ใช้` แสดงเป็น "ความคิดเดิม" คู่กับสิ่งที่ AI พบ · ขัดกัน = เขียนว่าขัดตรงไหน ไม่เขียนทับ
- หุ้นที่ผู้ใช้ใส่เองต้องมีแหล่งยืนยันเหมือนกัน · AI เสนอตัวที่ตรงกว่าแยกไว้
- บังคับหลักฐานขัดแย้ง ≥1 (กัน confirmation bias)

## 8b. จับคู่ list จาก TradingView screen (`match`)

**ทำไม:** มี list หุ้นจาก screener → อยากรู้ว่าตัวไหนเข้ากับไอเดียที่มีอยู่ โดยไม่ต้องให้ AI อ่านธุรกิจทุกตัว

**ขั้นตอน (ตะแกรง 3 ชั้น)**

| ชั้น | ใครทำ | ทำอะไร | token (ประมาณ) |
|---|---|---|---|
| 1 | แอป | ticker ตรง `candidates[]`/`losers[]` ของไอเดีย · หรือ Industry (TradingView) ตรง `chain.segments[].industries[]` | 0 |
| 2 | skill `match` | จากชื่อ + Industry → น่าเกี่ยว / ไม่แน่ใจ / ไม่เกี่ยว + ไอเดียไหน + ได้/เสีย + เหตุผล 1 บรรทัด · **ไม่ค้นเว็บ** · ตอบ "ไม่แน่ใจ" ได้ | ~3–5k / 50 ตัว |
| 3 | skill `pick` (เดิม) | หาแหล่งยืนยันเฉพาะตัวที่ผู้ใช้เลือกไปต่อ | ~2–3k / ตัว |

ตัวอย่าง list 100 ตัว ≈ 25–40k tokens รวม

**ในแอป**
1. หน้า Candidates → `📋 จับคู่ list` → วาง CSV (Symbol, Description, Industry) หรือ ticker ล้วน (ชั้น 1 เหลือแค่จับ ticker)
2. แอปแสดงผลชั้น 1 ทันที: ตรงไอเดีย · ตัดทิ้ง · ส่วนที่เหลือ
3. `คัดลอกคำสั่ง match` = ticker ที่ผ่านชั้น 1 + "สรุปไอเดียสำหรับจับคู่" (ไอเดียละ ~200 tokens: ประโยคเดียว · segments ได้/เสีย · industries) · ติ๊ก `ส่งตัวที่ถูกตัดด้วย` ได้ (token ชั้น 2 ราว ×2 แต่หลุดน้อยลง) · **ค่าเริ่มต้น = ส่งเฉพาะตัวที่ผ่านชั้น 1**
4. 📥 Import JSON `idea-match@1` → บริษัทเข้าไอเดียแต่ละอันสถานะ **รอตรวจ** (`state: "screen"`) · Candidates แสดง `▲?` / `▼?`
5. **บังคับ:** สถานะรอตรวจกด → Watchlist ไม่ได้ จนกว่ารัน `pick` แล้วมี `relevance_src`
- เฉพาะไอเดียสถานะ รอหลักฐาน / พร้อมส่งต่อ ที่ถูกใช้จับคู่ · list ที่วางไม่เก็บถาวร (เก็บแค่ผลที่ Import)

**JSON `idea-match@1`**
```json
{ "schema": "idea-match@1", "date": "YYYY-MM-DD", "source": "TradingView screen ...",
  "results": [{ "sym": "", "market": "US|TH", "idea": "<id>", "side": "win|lose", "segments": ["<ชื่อส่วน value chain>"],
                "fit": "likely|unsure", "why": "", "tag": "I" }],
  "dropped": 0, "audit": "" }
```
(ตัว "ไม่เกี่ยว" ไม่ต้องส่ง · บอกแค่จำนวนใน `dropped`)

**ส่วนของ value chain:** ทุกบริษัทต้องระบุ `segments[]` (ใช้ชื่อตาม `chain.segments[].name` ของไอเดียนั้นเท่านั้น · ส่วนหลักขึ้นก่อน) · จาก match = AI เดาจาก Industry/ชื่อ → แสดง `?` จนรัน `pick` ยืนยันจากรายได้แยก segment ของบริษัท · แสดงที่: ticker ในกล่อง Value chain · ป้ายใน Candidates (`ส่วน · ▲/▼`) · แท็บบริษัท

## 8c. ตอบข้อที่ขาด (ผู้ใช้ไปหามาเอง → AI ต่อยอด)

**ข้อที่ขาด (`gaps[]`)** มีระดับ + สถานะ
| ระดับ | ความหมาย | ผลต่อแอป |
|---|---|---|
| `must` ต้องรู้ | ไม่รู้ = ตัดสินไม่ได้ | เปิดอยู่ → ตั้ง "พร้อมส่งต่อ" ไม่ได้ |
| `track` ติดตาม | รู้ทีหลังได้ | — |
| `skip` ข้าม | ไม่คุ้มเวลาหา | ไม่แสดง (อยู่ในพับ) |

สถานะ: `open` เปิดอยู่ · `answered` ตอบแล้ว · `unanswerable` หาไม่ได้ (บริษัทไม่เปิดเผย ฯลฯ — ต้องมีเหตุผล + ใช้อะไรแทน หรือยอมรับความเสี่ยง)

**ในแอป**
1. แท็บหลักฐาน → แถวข้อที่ขาด → `📝 ตอบ` → sheet: ช่องวางข้อความ / ลิงก์ · แนบภาพหรือ PDF ทำในแชท AI (แอปบอกให้แนบ)
2. ปุ่ม `คัดลอกคำสั่ง` → `idea-scout update · ตอบข้อที่ขาด #id` + สิ่งที่วาง + JSON เดิม
3. ตอบหลายข้อพร้อมกันได้ (ติ๊กเลือก) · ปุ่ม `ปิดเป็น "หาไม่ได้"` ทำในแอปได้เลย (ไม่ใช้ AI · ต้องพิมพ์เหตุผล)
4. 📥 Import → ข้อนั้นเปลี่ยนสถานะ + เห็นคำตอบ + log บอกว่าคำตอบเปลี่ยนอะไรในไอเดีย

**AI เชื่อแค่ไหน (ป้าย)**
| ผู้ใช้ส่ง | ป้าย |
|---|---|
| เอกสารบริษัท (10-K · งบ · IR) ไฟล์ / ลิงก์ / ภาพหน้าจอ | `F` |
| ข่าว · บทวิเคราะห์โบรก | ตัวเลขบริษัทต้องยืนยันจากเอกสารบริษัท · ความเห็น = `I` |
| ความจำ / สิ่งที่สังเกตเอง | `U` |
| ขัดกับของเดิม | ไม่ทับ · แสดงทั้งสองฝั่ง + บอกว่าต่างตรงไหน |

token: AI อ่านเฉพาะสิ่งที่ส่งมา ไม่ค้นเว็บเอง ≈ 5–15k ต่อครั้ง

**Living Thesis (ทำทีหลังได้):** ใช้ปุ่ม `📝 ตอบ` แบบเดียวกันในตาราง `gaps[]` แท็บติดตาม → คำสั่ง `living-thesis update · ตอบ gap` · skill living-thesis โหมด update ปิด gap ได้อยู่แล้ว (เพิ่มแค่: รับสิ่งที่ผู้ใช้ส่ง + ป้าย U + สถานะ unanswerable)

## 8d. กลุ่มที่วิ่งแต่ยังไม่มีไอเดีย (ต่อจาก 📋 จับคู่ list · ไม่ใช้ token)

- ตอนวาง list (ต้องมีคอลัมน์ Industry) แอปนับหุ้นที่ **ไม่ตรงไอเดียไหนเลยในชั้น 1** แยกตาม Industry
- Industry ที่มี **≥3 ตัว** (ปรับได้ใน settings) → ขึ้นบรรทัดเดียวเหนือผลจับคู่: `กลุ่มยังไม่มีไอเดีย: Electrical Products (5) ＋ · Semiconductors (3) ＋` (สูงสุด 3 กลุ่ม เรียงจำนวนมาก → น้อย)
- กด `＋` → สร้างไอเดีย **ร่าง** ทันที: ชื่อ = `"{Industry} วิ่ง — เพราะอะไร?"` · `user_notes.idea` = "หุ้นกลุ่ม {Industry} ขึ้นพร้อมกันใน screen {วันที่}" · `user_notes.tickers` = รายชื่อหุ้นกลุ่มนั้น · `origin` = "TradingView screen {วันที่}"
- จากนั้น ⋯ → `คัดลอกคำสั่ง scan` → skill scan ตอบ "กลุ่มนี้วิ่งเพราะอะไร · เป็นแนวโน้มระยะยาว / วัฏจักร / เหตุการณ์ชั่วคราว · จะไปต่อได้ไหม"
- กลุ่มที่กด `ไม่สนใจ` → ซ่อน Industry นั้นจากบรรทัดนี้ 30 วัน (localStorage)
- ใช้ในกิจวัตร: Stock Selection US/TH · ไม่เกิน 1 กลุ่มต่อวันที่ควรกด
