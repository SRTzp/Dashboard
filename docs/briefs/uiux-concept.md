# UIUX concept — Trading Dashboard (SRTp) · applies to EVERY task

Check every brief, mockup, review and fix against these rules and say what fails. Updated 23 Nov 2026 (rule 11 = iPhone check, SRTp request).

1. Easy to read at a glance; plain words; no jargon; nothing cut with "…" (wrap instead; a clamp is allowed only with a visible `more`).
2. Simple — show only what needs action; normal state hidden or one line; details one tap away (drawer / fold).
3. No missing key detail (numbers, reason, the fix) — simple ≠ thin.
4. Nothing shown twice; remove duplicates across cards.
5. One screen where possible (1440×900 no page scroll; phone in a sensible order).
6. One primary (dark) button per screen/area; others outline.
7. Colour meaning: amber = to do / needs fix, red = money lost only, green = good/done, blue = info/distance. Pills are filled pills, never plain grey text or outlined boxes that look like buttons.
8. Same pattern everywhere (card lines, row anatomy, wording like `to entry` / `to level`, `#n` = share count, ①② = entries, tabular numbers, Inter, light theme).
9. Blocked/limited states name the fix ("⚠ … · Fix ›"), never a bare "Blocked".
10. Mockup first for anything visual; compare Original vs Proposed (pros/cons) when changing something.
11. **iPhone check (390×844) every time — before confirming a layout or sending a mockup.** Every mockup shows the desktop (1440) AND the iPhone (390) version; every CC brief lists 390 screenshots; every review looks at them. Phone checklist:
    - No "…" cuts anywhere (titles, sub-lines, tab labels, To do / Manage rows) — wrap or use a shorter phone label (e.g. `AI 2`).
    - No desktop label column on phone: labels go inline as small caps at the start of the row; content uses the full width (no empty left area).
    - No control on its own row just because it did not fit: filter chips = one horizontally scrollable row with icon actions pinned at its end.
    - Nothing runs past the card edge (long words / URLs wrap: `overflow-wrap:anywhere`); chips that do not fit → `+n`; no overlapping cards.
    - Tap targets ≥ 44px; one dark button per card; sensible order (Today: status → Act → Ideas → To do → Risk room).
    - Detail views open as a full-screen sheet with ✕; sheets scroll inside, page does not jump.

Process: mockups are small HTML pages checked with headless Chrome at 1440×900 AND 390×844 before sending.
