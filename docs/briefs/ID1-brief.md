## 1. ที่เก็บข้อมูล
- Firestore `users/{uid}/ideas/{id}` (id จาก JSON · `[a-z0-9-]` ≤ 60 ตัว) · **เพิ่ม rules** แบบเดียวกับ `users/{uid}/watchlist` + อัปเดตสำเนา rules ใน repo
- field:
  - `idea` = JSON ทั้งก้อน **ยกเว้น `log`**
  - `idea_log` = array (append เท่านั้น · key = `date + new`)
  - `user` = ค่าที่ผู้ใช้ตั้งในแอป: `{ status, pick: {"<ชื่อส่วน>": true}, cand: {"<SYM>": {rank, state}}, updated_at }`
- แสดงผล = `idea` ทับด้วย `user` (ผู้ใช้ชนะเสมอ) · **Import ใหม่แทนที่ `idea` เท่านั้น ไม่แตะ `user`**
- โหลดตอน login คู่กับ `wlStart()` (ฟังก์ชันใหม่ เช่น `ideaStart()`) · state หน้าจอ (`ideaSel`, `ideaTab`, `ideaFilter`) ห้ามเก็บลง Firestore

## 5. การ์ดไอเดีย (ตามม็อกอัป v2)
หัว: ชื่อ · ป้ายสถานะ (กดเปลี่ยนได้ ข้อ 6) · ตลาด · ประเภท · `idea@1 · {mode} · {date}` · ปุ่ม `⋯` (Export JSON · ประวัติ log · ลบ ตามข้อ 6)

| กลไก | เส้นเหตุ-ผลขั้นบันได (`weak` = ส้ม + "จุดเชื่อมที่ไม่แน่นอนที่สุด") · ใครจ่าย · ทำไมต้องจ่าย · ทางเลือกอื่น · จุดอ่อนสุด |

| บริษัท | รายการเรียงตาม rank (null ท้ายสุด) · แถวบรรทัดเดียว: rank · SYM · ชื่อ · ส่วน · สถานะ · แตะเปิดรายละเอียด: ธุรกิจที่เกี่ยว · ได้ประโยชน์ผ่าน · นัยต่อทั้งบริษัท · ทำไมตัวนี้ · ไม่ได้ประโยชน์แม้ไอเดียถูกถ้า · คำถามให้ Thesis · แหล่งยืนยัน · **ยังไม่มีปุ่ม → Watchlist / Handoff (ID2)** |

## 6. สิ่งที่ผู้ใช้แก้ได้ในรอบนี้
- **สถานะไอเดีย** (กดป้าย): กำลังสำรวจ · รอหลักฐาน · พร้อมส่งต่อ · พัก · **พร้อมส่งต่อกดไม่ได้** ถ้าไม่ผ่าน 4 ข้อ: evidence `against` ≥1 · kill ≥1 · บริษัท `study` ที่มี `relevance_src` ≥1 · ไม่มี gap `must` ที่ `open` → แสดงเหตุผลที่ขาด
- **เลือกส่วน value chain** (checkbox) · **สถานะ/ลำดับบริษัท** (เมนูเล็ก: ศึกษา · รอข้อมูล · พัก · เลื่อนลำดับขึ้น/ลง) · บริษัทที่ไม่มี `relevance_src` ตั้งเป็น "ศึกษา" ไม่ได้
- **ลบ**: ไอเดียสถานะพักเท่านั้นในรอบนี้ → `⋯ ลบ` → หน้าต่างยืนยัน → ดาวน์โหลด `{id}_idea_backup_{YYYYMMDD}.json` (= Export) → ลบ doc · สถานะอื่นในเมนู `ลบ` เป็นสีเทา + "ตั้งเป็น พัก ก่อน"

## 7. Import / Export
- `📥 Import` (หัวรายการ + `⋯` ของการ์ด): ช่องวาง + เลือกไฟล์ `.json` · ตัด ```json fence / ข้อความหน้า-หลังได้ (ใช้ตัวตัดแบบที่ Thesis ใช้)
- ตรวจ: parse ได้ · `schema==="idea@1"` · มี `id` · `name` · `idea` object · `chain.segments` array · ≤200KB · ผิด = ข้อความไทย ไม่บันทึก · `idea-match@1` = "ไฟล์จับคู่ ใช้ใน ID3" ไม่บันทึก
- id ใหม่ → สร้าง · id มีอยู่แล้ว → diff สั้นก่อนยืนยัน: mode เดิม→ใหม่ · จำนวนบริษัท · kill ที่ level เปลี่ยน · gaps ที่ปิด · `บันทึก`
- บันทึก: `idea` แทนที่ · `idea_log` append เฉพาะบรรทัดใหม่ · **`user` ไม่แตะ** · ถ้า `user.cand` มี SYM ที่ไม่อยู่ในไฟล์ใหม่ → เก็บไว้เฉย ๆ (ไม่แสดง)
- `⋯ Export JSON`: idea + `log: idea_log` + **ค่าจาก `user` ทับลงใน field จริง** (status · segments[].pick · candidates[].rank/state) → คัดลอก + ดาวน์โหลดได้ · ข้อความ "คัดลอกแล้ว — แนบให้ idea-scout pick/update"
