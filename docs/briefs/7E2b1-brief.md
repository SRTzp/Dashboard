## 4. ฟอร์ม / sheet
### 4.1 แผน Core ใหม่ (`coreNewOpen` บรรทัด ~5343) — เพิ่ม Tier คำนวณ + สลับกลยุทธ์
ลำดับช่อง: บัญชี · Ticker · **Tier (บล็อกใหม่)** · **กลยุทธ์ [ระบบ Week | ถัวตามแนวรับ]** · (W: ช่องเดิมทั้งหมด) / (L: ฟอร์มบันได)
- **บล็อก Tier** (ใช้ซ้ำใน sheet "Tier…"): 
  - ROIC % · ND/EBITDA (เท่า) · FCF conversion % (พิมพ์เป็น % → เก็บเศษส่วน) · Gate 5 สามข้อ ปุ่ม [ใช่] [ไม่ใช่] (เริ่ม = ยังไม่ตอบ): (1) ของแทนที่ถูกกว่า/ดีกว่าเริ่มมีคนใช้ (2) ลูกค้าหลักเริ่มย้าย (3) รายได้ > 50% จากสินค้าเดียวที่โดนข้อ 1
  - ผลสด `classifyTier` : "คำนวณได้ **A**" หรือ "คำนวณได้ **B** · ไม่ผ่าน: ROIC ≤ 12% · Gate 5 ข้อ 2 = ใช่ · ยังไม่ตอบ 1 ข้อ"
  - ปุ่ม Tier ที่ใช้จริง [B] [A] เริ่ม = ผลคำนวณ · เลือก A ขณะคำนวณได้ B → ช่อง "เหตุผล (บังคับ)" (`override`) · เลือก B ขณะคำนวณได้ A → ไม่ต้องมีเหตุผล
  - เก็บ `tier` · `tierComputed` · `tierInputs {roic, ndEbitda, fcfConv, gate5:{substitute, customerMigrating, singleProduct}}` · `tierReason` (มีเฉพาะ override A)
  - ช่องว่างทั้งหมด = คำนวณได้ B (ใช้แบบเดิมได้ — เลือก A + เหตุผล)
- **สลับกลยุทธ์:** Tier ที่ใช้จริง = B → ปุ่ม L ปิด + "L ใช้ได้เฉพาะ Tier A"
- **ฟอร์ม L:**
  - ระดับราคา L1 · L2 · [+ ระดับ 3] (ลบได้ · 2–3 ระดับ · ต้องเรียงลดลง) · SL ตัวเดียว (ต่ำกว่าระดับสุดท้าย) · งบ % ของถัง (ค่าเริ่ม = `cfg.ladderBudget` · สูงสุดเท่านั้น · แสดง ฿ ข้าง ๆ) · แบ่งเงิน: 3 ระดับ = 40/30/30 · 2 ระดับ = 50/50 (ปรับเองได้ → v2)
  - ผลสด: ตารางบันได (ข้อ 3.2) + สรุป + **ประตู 5 ข้อ ✓/✗** (`coreCanPlace`)
  - error จาก `ladder()` เป็นข้อความไทย: LEVELS_NOT_DESC "ระดับต้องเรียงจากสูงไปต่ำ" · LEVEL_BELOW_SL "ทุกระดับต้องสูงกว่า SL" · ZERO_LOT_Lk "Lk ได้ 0 หุ้น — เพิ่มงบหรือลดจำนวนระดับ"
  - ปุ่ม **"ล็อกแผน"** ใช้ได้เมื่อ: ประตูครบ 5 ข้อ · ไม่มี ZERO_LOT · ticker/บัญชีผ่านเหมือน W (ไม่ซ้ำการ์ดเปิด) · ไม่มี coreErr · RISK_OVER = เตือนแดงแต่ไม่บล็อก
  - บันทึก: `ladder.lockedAt = now` · `stop = sl` · `status:'plan'`
- ตัดข้อความ f ซ้ำ: `cnFsrc` ไม่ต้องแสดงที่มา `(Fund-flow เก่า · ไม่ลด)` เมื่อชิปเตือน `cnFwarn` แสดงอยู่ (เหลือแค่ "(เลือกเอง · ระบบ x%)" ถ้าผู้ใช้เลือกเอง)
