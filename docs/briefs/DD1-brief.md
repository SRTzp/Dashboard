## 0. แก้ก่อน (เจอตอนตรวจ PY1 · DD1 ต้องใช้ R และ heat ที่ถูก)
1. **R ใน Journal ใช้ SL ตอนเข้า ไม่ใช่ SL ปัจจุบัน:** ตอนนี้ `realizedROf` ใช้ `riskOf(t)` = |entry − sl ปัจจุบัน| → ไม้ที่เลื่อน SL (trailing / ย้ายไปทุน) R เพี้ยนหรือเป็น "—" (กระทบ avg R · เกณฑ์พิสูจน์ 50 ไม้ avg R ≥ 0.25 · และ +2R ของ DD1)
   - เก็บ `sl0` (SL ตอนเข้า) ให้**ทุกไม้ใหม่**ใน `makeTradeObject` (Core + Sat · ไม้เติมมีแล้ว) · แก้ SL ภายหลัง (`openTradeEdit` · การ์ด Core เลื่อน Stop) **ไม่แตะ `sl0`** · แก้ไม้สถานะ plan (ยังไม่เข้า) = อัปเดต `sl0` ตาม
   - `realizedROf`: มี `sl0 > 0` → ใช้ |entry − sl0| · ไม่มี (ไม้เก่า) → พฤติกรรมเดิม
   - Core ที่มี `stopHistory` → ไม้เก่าใช้ stop แรกใน history เป็น sl0 ได้ (ถ้ามี) — ตีความแล้วจดในรายงาน
2. **heat แถบบัญชี Sat:** `sat7dAcctBase` คิด openRisk = |entry − sl| × qty ตรง ๆ → ไม้ที่ SL เลยทุนถูกนับเป็นความเสี่ยง · เปลี่ยนให้ใช้ `posOpenRisk(t)` (SL เลยทุน = 0) แบบเดียวกับ `openRiskTHB` · ตัวเลข heat ใน sheet เติมไม้ (PY1) กับแถบต้องตรงกัน
3. ข้อความเล็ก PY1: เหตุผลสวน Bias บนปุ่มเติมไม้ใช้ `สวน Bias สัปดาห์ (ตอนนี้ {X}) — เติมไม้ไม่ได้` (แทนข้อความ "ยกเลิกแผนนี้…" ที่ใช้กับแผนยังไม่เข้า) · sheet เติมไม้ "ความเสี่ยงไม้ 1 หลังย้าย SL ร่วม" แสดงเป็น ฿ (ตอนนี้แสดง USD)
- เทส: เพิ่มใน phase37 (หรือ phase36 ต่อท้าย): ไม้ Long entry 100 SL 90 → เลื่อน SL 105 → ปิด 120 → R = 2.0 (ไม่ใช่ 4.0/—) · ไม้เก่าไม่มี sl0 → R เดิม · heat แถบ = 0 สำหรับไม้ SL เลยทุน · เคสเก่าที่คาด R/heat จาก SL ปัจจุบัน → แก้ความคาดหวัง + จดใน DD1_retired.md

## 1. ตัวคำนวณ (ไม่แตะ DOM · ใส่ใน core-size.js เป็น `Calc.coreSize.ddStage` หรือ namespace ใหม่ `Calc.dd` ที่ sync เข้า index ด้วย `tools/sync_core_size.py` · เทสใน `core_size_test.js`)
`ddStep({equity, peak, stage, stageSince, belowWeeks, pauseWeeks, pauseUntil, reviewDone, recoverR, cfg, weekKey})` → state ใหม่ + `{ddPct, stage, sizeFactor, allowNew, reasons[]}`
- `ddPct = max(0, (peak − equity) / peak × 100)` · equity > peak → peak = equity
- stage:
  | stage | เข้าเมื่อ | ผล | ออกเมื่อ |
  |---|---|---|---|
  | `normal` | — | ×1 | DD ≥ `ddReduce` → `reduce` · DD ≥ `ddPause` → `pause` |
  | `reduce` | DD ≥ 12.5 | ไม้ใหม่ ×0.5 · Core: งดเปิดบันได L ใหม่ | DD < `ddReduce` ติดกัน 2 สัปดาห์ (snapshot รายสัปดาห์) → `normal` · DD ≥ `ddPause` → `pause` |
  | `pause` | DD ≥ 20 | **ห้ามเปิดไม้ใหม่ / บันไดใหม่** | ครบ `pauseWeeks` (Core 2 · Sat 1) **และ** เขียนทบทวนแล้ว → `recover` |
  | `recover` | หลังพัก | ไม้ใหม่ ×0.5 · Core: งดบันได L ใหม่ | กำไรสุทธิจากไม้ที่ปิดตั้งแต่เข้า recover ≥ `recoverR` × 1R (1R = RPT ปกติ × ถัง) **หรือ** DD < `ddReduce` ติดกัน 2 สัปดาห์ → `normal` · DD ≥ `ddPause` อีกครั้ง → `pause` (นับเวลาพักใหม่) |
- **ทำได้เสมอทุก stage:** เลื่อน Stop · ขาย/ปิดไม้ · Stop ฉุกเฉิน · **เติมไม้ตัวที่ Stop ≥ ทุนเฉลี่ยแล้ว** (Core ไม้เติม · Sat PY1) — ขนาดไม้เติมตามกติกาเดิม (ไม่คูณ 0.5)
- ค่าทั้งหมดรับจาก cfg · ไม่อ่านนาฬิกาเอง (รับ weekKey/today จากข้างนอก)

## 2. equity ต่อถัง ต่อบัญชี
- **Core:** `ทุนถัง Core (settings) + Σ P&L ไม้ Core ที่ปิดตั้งแต่ baseAt + Σ กำไร/ขาดทุนไม้ Core ที่ถือ (qty × (ราคาปิดสัปดาห์ − ทุนเฉลี่ย))` · ตัวที่ไม่มีราคา = 0 + บอก `ขาดราคา n ตัว` (ใช้ px/pxDate เดิมของการ์ด)
- **Sat:** `ทุนถัง Sat (THB) + Σ P&L ไม้ Sat ที่ปิดตั้งแต่ baseAt` — ไม้ Sat ที่เปิดอยู่**ไม่มีราคาสด** จึงไม่นับ (คุมด้วย heat อยู่แล้ว) · เขียนเหตุผลนี้เป็นคอมเมนต์
- **ผู้ใช้แก้ทุนถังในค่าตั้ง** → rebase: peak = equity ใหม่ · baseAt = วันนี้ · stage = normal · แจ้งบรรทัดเล็ก "เริ่มนับ DD ใหม่ (แก้ทุนถัง)"
- เก็บ state ต่อบัญชีใน `settings.ddState = {core:{peak, baseAt, stage, stageSince, pauseUntil, review, recoverStart, weekly:{weekKey: ddPct}}, sat:{…}}` · `weekly` เก็บ 12 สัปดาห์ล่าสุด · อัปเดต snapshot สัปดาห์ปัจจุบันทุกครั้งที่คำนวณ (ค่าล่าสุดของสัปดาห์ชนะ) · "ติดกัน 2 สัปดาห์" = 2 สัปดาห์ที่จบแล้วล่าสุด (ไม่นับสัปดาห์ปัจจุบัน)
- คำนวณใหม่ตอนเปิดแอป / หลังบันทึกไม้ / ปิดไม้ / กรอกราคาปิด · เขียน settings เฉพาะเมื่อค่าเปลี่ยน (ไม่เขียนรัว)

## 3. ผลต่อการเข้าไม้ (บล็อกจริง · ไม่มีทางลัด)
- **Core W ไม้แรก:** ส่ง `riskPct × sizeFactor` เข้า `coreSizeOpts` · `pause` → ปุ่มบันทึกแผน/ซื้อไม้ 1 ปิด + เหตุผล `เบรก DD: พักถึง {date} — เลื่อน Stop/ขาย/เติมตัวที่กำไรได้`
- **Core L บันไดใหม่:** `reduce`/`pause`/`recover` → เปิดไม่ได้ + เหตุผล (ระดับที่จองไว้แล้วซื้อต่อได้ตามแผน)
- **Core ไม้เติม:** ทุก stage ทำได้ถ้า Stop ≥ ทุนเฉลี่ย · ถ้า Stop < ทุน และ stage ≠ normal → บล็อก `เบรก DD: เติมได้เฉพาะตัวที่ Stop ≥ ทุน`
- **Sat:** `rpt × sizeFactor` ใน `sat7dAcctBase` · `pause` → ทุกบัญชีไม่ ready + เหตุผล · **ไม่มี "รวมด้วย (นอกแผน)"** · ฟังก์ชันบันทึก order กันซ้ำในโค้ด (แบบเดียวกับ `satOffBias`) · PY1 เติมไม้ทำได้ตามกติกา PY1
- **บันทึกไม้ย้อนหลัง** (backfill) ไม่ถูกบล็อก (เป็นการลงบันทึก ไม่ใช่เปิดความเสี่ยงใหม่)

## 4. หน้าจอ
- แถบบัญชี Core และ Sat: ชิป `DD x%` + สถานะ — ปกติ (เทา) · `ลดขนาด ×0.5` (เหลือง) · `พักถึง {d MMM}` (แดง) · `ฟื้นตัว +x.xR / 2R` (ฟ้า)
- stage ≠ normal → แถบแจ้งบนส่วน Core / Sat ของบัญชีนั้น 1 บรรทัด + ลิงก์ "รายละเอียด" → sheet: กราฟเล็กไม่ต้องมี · ตาราง snapshot รายสัปดาห์ (สัปดาห์ · DD%) · เกณฑ์ · เวลาที่เหลือ
- `pause`: ปุ่ม **"เขียนทบทวน"** → ช่องข้อความ (≥ 20 ตัวอักษร) "ผิดตรงไหน / จะแก้อะไร" → เก็บ `review{text, at}` · ครบเวลา + มีบันทึก → `recover` อัตโนมัติ
- Core DD ≥ 20%: ใน sheet แสดง **ตัวที่อ่อนสุด 3 ตัว** (เรียงจากขาดทุนเป็น R มากสุด → ห่าง Stop น้อยสุด) · ข้อความ "ทบทวน ลดตัวอ่อนสุด — คุณตัดสินใจเอง" · ไม่ขายให้
- ค่าตั้ง: Core (`coreRisk`) เพิ่ม `ddReduce 12.5 · ddPause 20 · ddPauseWeeks 2 · ddRecoverR 2` · Sat (`satRisk`) เพิ่ม `ddReduce 12.5 · ddPause 20 · ddPauseWeeks 1 · ddRecoverR 2` · ตรวจ: 0 < reduce < pause ≤ 50 · pauseWeeks จำนวนเต็ม 1–8 · recoverR 0.5–10 · ป้ายหน่วยทุกช่อง
