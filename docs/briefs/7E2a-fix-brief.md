## 1b. ป้ายนับไม้ `#n/N` + ค่าตั้ง "จำนวนไม้สูงสุด"
- ค่าตั้งใหม่ต่อบัญชี `settings.coreRisk.maxLots` (ค่าเริ่มต้น **3** · ช่วง 1–6 จำนวนเต็ม) · เพิ่มใน `CORE_RISK_DEFAULTS` + ฟอร์มค่าตั้ง Core ข้างช่อง "ไม้เติม %" (`sCrAdd`) · id `sCrMaxLots` · ค่าผิด (0 · 7 · 2.5 · ว่าง) → ไม่บันทึก + ใช้ 3 · หมายเหตุ: coreRiskCfg ตอนนี้รับทุกค่า > 0 → ต้องตรวจช่วง/จำนวนเต็มเพิ่มสำหรับ maxLots
- ใต้ 2 ช่องนี้ บรรทัดตัวอย่างสด: "ตัวอย่าง: ไม้แรก 100 → 50 → 25 (รวม 175% ของไม้แรก)" คำนวณจาก addRatio × maxLots (แค่แสดง ไม่ใช่สูตรใหม่)
- n = `lots.length` ของการ์ด (ไม่มี lots แต่มี trade = 1) · N = maxLots ของบัญชี
- แถวยุบ: ป้าย `#2/3` ต่อจาก `B·W` (แสดงทั้ง desktop + มือถือ) · ครบ → `#3/3 ครบ` สีเทา · เกิน (ลด N ทีหลัง) → `#4/3` สีเหลือง

- n ≥ N → ปุ่ม `เติมไม้` disabled + title "ครบ N ไม้แล้ว" · coreSimCalc เพิ่ม blocked "ครบ N ไม้แล้ว" (ห้ามเปลี่ยนตัวเลขอื่น)
