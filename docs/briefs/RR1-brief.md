## 1. หาตัวกระตุ้น (ทำก่อนแก้)
- ไล่ทุกจุดที่เรียก `satV3Render()` / `render()` ระหว่างอยู่แท็บ แผน: onSnapshot ทุกตัว (settings · satIdeas · trades · satWeek · ideas · watchlist …) · setInterval / setTimeout · event `mousemove` `pointerover` `focus` `scroll` `resize` `visibilitychange` · ResizeObserver / IntersectionObserver · `img onload` ที่สั่ง render ต่อ
- เพิ่มตัวนับเพื่อดีบัก: เปิดด้วย `?debug=render` (หรือ `localStorage.dbgRender=1` · try/catch) → ป้ายเล็กมุมจอ: จำนวนครั้งที่ `satV3Render` ถูกเรียก + สาเหตุล่าสุด 5 รายการ (ชื่อตัวเรียก เช่น `snap:settings` `timer:news` `event:resize`) · ปกติปิด ไม่มีผลกับผู้ใช้
- รายงาน: เจออะไรเป็นตัวกระตุ้น (ถ้าหาไม่เจอจากโค้ด บอกตรง ๆ + ให้ผู้ใช้เปิด `?debug=render` บนเว็บจริงแล้วส่งภาพป้ายมา)

## 2. แก้ให้วาดใหม่เฉพาะเมื่อข้อมูลเปลี่ยน
- `satV3Render`: คำนวณ HTML ใหม่ → ถ้าเหมือนของเดิมทุกตัวอักษร **ไม่แตะ DOM** · onSnapshot ที่ข้อมูลไม่เปลี่ยน (เช่น เสียงสะท้อนจากการเขียนของตัวเอง `hasPendingWrites` / metadata-only) → ไม่ render
- **ภาพกราฟไม่โหลดใหม่:** ถ้าต้องวาดใหม่ ให้ย้าย `<img>` ตัวเดิม (URL เดิม) กลับเข้าไปแทนการสร้างใหม่ หรือแยกแถบกราฟออกจากส่วนที่วาดใหม่ · ภาพโหลดใหม่เฉพาะเมื่อ URL เปลี่ยน
- **จองที่ให้ภาพก่อนโหลดเสร็จ** (aspect-ratio / ความสูงคงที่) → หน้าไม่กระโดดตอนภาพโหลด (ปิดข้อ polish "image load jump")
- **ตัวที่เลือกไม่หาย:** `satV3Sel` + แถวแก้ Strategy ที่เปิดอยู่ + ช่องที่กำลังพิมพ์ (focus · ตำแหน่ง cursor · ค่าที่พิมพ์ค้าง) คงเดิมหลังวาดใหม่ · scroll ไม่กระโดด
- แท็บอื่นที่ใช้รูปแบบเดียวกัน (Today · Watch การ์ด · Ideas) ถ้าพบตัวกระตุ้นเดียวกัน → ใช้กติกาเดียวกัน (รายงานว่าแก้ที่ไหนบ้าง)
