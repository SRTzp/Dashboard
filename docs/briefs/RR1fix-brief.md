## 1. สาเหตุ (Orchestrator วิเคราะห์ · CC ยืนยัน)
- p69 เคส 6: ช่อง `[data-macro-note]` มีโฟกัส → `change` → บันทึก → `satV3Render()` → `replaceChildren` เอาช่องที่โฟกัสอยู่ออก → เบราว์เซอร์ยิง `blur` ระหว่างนั้น → handler ของ blur/change เรียก `satV3Render()` ซ้อน → render ตัวใน แทนลูกของ `el` ไปแล้ว → `replaceChildren` ตัวนอกหา node เดิมไม่เจอ → error (Mac อาจไม่ยิง blur ตอนนั้น จึงไม่เห็น · Linux headless เห็นทุกครั้ง)
- ผลกับผู้ใช้จริง: การวาดรอบนั้นค้างครึ่งทาง (หน้าอาจไม่อัปเดต) + error ใน console

## 2. แก้
- `satV3Render` **กันเรียกซ้อน:** ถ้ากำลังวาดอยู่ → จดว่า "ต้องวาดอีกรอบ" แล้ว return · วาดเสร็จ → ถ้ามีจด ให้วาดอีก 1 รอบ (ด้วย force ถ้าตัวที่ถูกเลื่อนขอ force) · ไม่วนไม่จบ (สูงสุด 2 รอบต่อการเรียก)
- ก่อน `replaceChildren`: ถ้าช่องที่โฟกัสอยู่ใน `el` → `blur()` ก่อน (ภายใต้ตัวกันซ้อน) แล้วคืนโฟกัสตามระบบ RR1 เดิม
- จุดอื่นที่ RR1 ใช้รูปแบบเดียวกัน (`todayRefresh` ฯลฯ) → ตรวจว่ามีโอกาสซ้อนไหม · ใช้ตัวกันเดียวกันถ้ามี
