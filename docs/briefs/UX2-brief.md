## 1. Filter รวม (Watchlist และ Candidates)
- แทน 3 แถว (`data-cand-filters` · `data-tq-filters` · `data-ph-filters`) ด้วย **แถวเดียว**: ปุ่ม `Filter (n) ▾` + บรรทัดสรุปสีจาง (ตัด `…` ถ้ายาว)
  - n = จำนวนค่าที่เลือก (Idea ≠ ทั้งหมด นับ 1 · Tier ทีละค่า · Phase ทีละค่า) · ไม่นับการเรียง · n = 0 → ไม่แสดงตัวเลข
  - สรุป: ค่าที่เลือกคั่น ` · ` เช่น `Idea ▲ · Up` · ถ้าเรียง Phase อยู่ ต่อท้าย `· เรียง Phase` · ไม่มีอะไร = ว่าง
- กด → กางแผงใต้ปุ่ม (ปุ่มเปลี่ยนเป็น `▴` · บรรทัดสรุปเปลี่ยนเป็นลิงก์ `ล้างทั้งหมด` ถ้า n > 0) · กดอีกครั้ง = พับ · สถานะกาง/พับเก็บในหน่วยความจำ (เริ่มพับ)
- กลุ่มในแผง (หัวกลุ่มตัวเล็กสีจาง):
  - **Idea** (Candidates เท่านั้น): `▲ ได้` · `▼ เสีย` — เลือกได้ทีละค่า แตะซ้ำ = ทั้งหมด (ค่าเดิม `candFilter` all/win/lose · ตัดชิป `ทั้งหมด` ออก)
  - **Tier** (Candidates เท่านั้น): `ผ่าน` · `ไม่ผ่าน` · `ยังไม่ Check` (ค่าเดิม `tqFilter` pass/fail/none)
  - **Phase** (ทั้ง 2 view): `Start▲` · `Up` · `Side` · `Weak▼` · `—` (ค่าเดิม `phFilter`)
  - **เรียง**: Candidates `ตาม Idea` | `Phase` · Watchlist `ปกติ` | `Phase` (ค่าเดิม `phSort` · เลือกได้ 1)
- พฤติกรรมกรอง/เรียง/localStorage/คีย์ลัด `[ ]` เหมือนเดิมทุกอย่าง (แค่ย้ายที่แสดง) · คีย์ลัด `[ ]` ไม่แสดง hint ในแผงบนจอ ≤ 480px
- ปุ่ม Port (All · Core.US · Core.TH) ของ Watchlist **คงที่เดิม** ไม่ย้ายเข้าแผง
- 390px: แถว Filter บรรทัดเดียว · แผงกางไม่ล้นแนวนอน (ชิปตัดบรรทัดในกลุ่มได้) · ชิปสูง ≥ 32px

## 2. Card แผน Core (`coreCardHtml` ส่วน `v.kind==='plan'` เท่านั้น · การ์ด open/L/closed ไม่แตะ)
เรียงใหม่ตามม็อกอัป:
1. แถวหัว (ปุ่ม `ccRow`): **ตอนกางอยู่** ซ่อน `ccNums` (Entry/Stop/ไม้แรก) · ตอนพับยังแสดงตามเดิม
2. ชิป: `Tier A · Fortress` (ตัด ` · เพดานไม้แรก x%` ออกจากชิป Tier **เฉพาะการ์ดแผน** — ไปอยู่บรรทัด FF · การ์ด open/L ใช้ชิปเดิม) · ชิปอื่นเดิม
3. **เตือนรวมบรรทัดเดียว** `⚠ …` = phase warn (PH1 `phCoreWarn`) + Tier badge ระดับ warn (`coreTierBadges` level warn) คั่น ` · ` · badge ระดับ muted ยังเป็นชิปเดิม · ไม่มีเตือน = ไม่มีบรรทัด
4. `Entry 100 · Stop 90` บรรทัดเดียว (อ่านอย่างเดียวเหมือนเดิม · แก้ผ่านเมนู ⋯ เดิม)
5. **ตัวใหญ่** `131 หุ้น` (+ ป้าย `เงินสดคุม` / `ชนเพดาน Tier` เฉพาะเมื่อเกิด · ป้าย `f x%` ตัดออก)
6. `ทุน $13.1k (7.5%) · Risk $1.31k (0.75%)` — **สกุลเดียวตามตลาด** (US = $ · TH = ฿) · ตัด ≈฿ ซ้ำ · % = ของถัง Core
7. `FF 75% · เพดานไม้แรก 15%`
8. คำเตือน zero-lot (`data-c-zero` · `data-c-zero-tier`) และข้อความ `กรอก Entry และ Stop` / `ยังไม่ได้ตั้งถัง Core` ยังแสดงนอกส่วนพับ
9. `วิธีคิด ▸` = `<details>` พับไว้ ข้างในมี: เงินสดว่าง + งบ Risk × DD × FF (`data-c-cash`) · ปัดหลัก/ปัด 1 หุ้น (`data-c-round`) · ที่มาของ FF (`cx.F.src`) · คุมด้วยอะไร (ข้อความ `ctl` เดิม)
10. ปุ่มเดิม (บันทึกซื้อไม้ 1 · ลบแผน · ⋯) · บล็อก DD/บล็อกซื้อเหมือนเดิม
- **ตัดออก:** กล่อง 4 ช่อง `ccGrid4` (Entry แผน · Stop แผน · f ตอนนี้ · ไม้แรก) ของการ์ดแผน
- **คง data-attribute เดิม** (`data-c-qty` · `data-c-cost` · `data-c-cash` · `data-c-round` · `data-c-tag` · `data-c-first` · `data-c-msg` · `data-c-buy1` ฯลฯ) ไว้ที่องค์ประกอบใหม่ที่ตรงความหมาย เพื่อให้เทสเก่าหาเจอ (ที่อยู่ใน `<details>` ต้องยังอยู่ใน DOM)
- ตัวเลขเงิน: ฟอร์แมตย่อ `k`/`M` ใช้ฟังก์ชันเดิมของแอปถ้ามี (เช่น `coreMoneyS`) · ไม่เขียนฟอร์แมตใหม่ถ้ามีของเดิม

## 3. `f` → `FF` (fundflow) ทุกจุดที่ผู้ใช้เห็น
- ป้าย/ข้อความ/title/placeholder ทุกที่ที่ `f` หมายถึงตัวคูณ fundflow → `FF` เช่น `f ตอนนี้` · `× f` · `งบเสี่ยง … × f` · `ประตู f` (ตั้งค่า + Today + หัวบัญชี) · `คุมด้วยงบเสี่ยง × f x%` · `f < 100%`
- **ไม่เปลี่ยน** ชื่อตัวแปร/ฟังก์ชัน/คีย์ Firestore/คีย์ settings (`cx.F.f` · `ffBizDaysSince` · `gateWeeks` ฯลฯ) และคอมเมนต์ในโค้ด
- วิธีหา: grep ข้อความไทยรอบ ๆ `f` ใน template string (`'f '` · `× f` · `f ${` · `ประตู f` · `>f<`) แล้วตรวจทีละจุด · รายงานรายการจุดที่เปลี่ยน (บรรทัด + ข้อความเดิม → ใหม่)
