# SR1 — ค่าตั้งความเสี่ยง Sat ต่อบัญชี (เสี่ยงต่อไม้ 1.5/2% · heat · ไม้ใหม่/สัปดาห์) + ปิด MR + ห้ามเทรดสวน Bias · เทส 34

> ผู้ใช้ 1 ต.ค.: "Port Sat ไม่มีกำหนด risk per trade size เหมือน fix ไว้เลย เปลี่ยนไม่ได้" → ตัดสิน: ปรับได้ 3 อย่าง **แยกต่อบัญชี** — เสี่ยงต่อไม้ (ปกติ / ผ่านเกณฑ์พิสูจน์) · heat รวม · ไม้ใหม่ต่อสัปดาห์ · **ไม่ทำ**ตัวคูณสวน Bias/MR 0.6 (คงเดิม)
> ผู้ใช้เพิ่ม (1 ต.ค. ดึก): **ค่าเริ่มต้นเสี่ยงต่อไม้ = 1.5% · เทรดดี (ผ่านเกณฑ์พิสูจน์) = 2%** (ปรับได้ทีหลังในค่าตั้ง) · **ปิด MR ไว้ก่อน** — Sat ใช้ "1 Bias · 1 ทิศ · 1 Setup" · ห้ามลบโค้ด MR (เผื่ออนาคต) · **ห้ามเปิดไม้สวน Bias สัปดาห์ทุกกรณี** ("เสียวินัย ไม่คุ้ม")
> ตอนนี้ฝังในโค้ด: `const SAT7D_RPT = 1.25, SAT7D_RPT_HI = 1.5, SAT7D_HEAT_MAX = 6, SAT7D_NEW_MAX = 2` (~8883) · ป้าย `STRIP_FIELDS.sat` (`/6%` · `/2`) · แถบบัญชี Sat (~9964)
> **พบระหว่างเตรียม brief:** ค่าตั้งมีช่อง "Sat — % ของถัง Sat" (`#sPortSatB` → `limits.port.satB`) อยู่แล้ว แต่การ์ด Sat / ความพร้อม (readiness) ใช้ `SAT7D_HEAT_MAX` ตายตัว ไม่อ่านช่องนี้ → รอบนี้ให้ใช้ค่าเดียวกัน
> สำรองก่อนแก้: `index.backup-pre-SR1.html` · **ห้ามแตะ** core-size.js · Core · `Calc.satLot` / `Calc.heat` / `Calc.readiness` (ส่งค่าเข้าเหมือนเดิม แค่เปลี่ยนที่มา) · `SAT_MACRO_CUT` · ห้ามลบโค้ด MR · ตัวนับพิสูจน์ (`SAT7D_PROVE_N/R`) · หน้าตาการ์ด Sat
> ใช้ชื่อฟังก์ชันเป็นหลัก (เลขบรรทัดอ้างจากไฟล์หลัง WT1 · 1,033,277 bytes)

## ข้อมูล (ต่อบัญชี · `settings` ของแต่ละ book)
- ใหม่ `settings.satRisk = {rpt, rptHi, newMax}` เก็บเป็น "% ตัวเลข" แบบเดียวกับ `coreRisk` · ค่าเริ่มต้น **`{rpt:1.5, rptHi:2, newMax:2}`** (เดิมในโค้ด 1.25/1.5) · ไม่มี/ผิด = ค่าเริ่มต้น (ไม่ migrate)
- heat Sat = `limits.port.satB` (ช่องเดิม · ค่าเริ่มต้น 6) — **ไม่เพิ่มฟิลด์ใหม่**
- helper ใหม่ `satRiskCfg(accId)` → `{rpt, rptHi, heatMax, newMax}` อ่านจาก book ของบัญชีนั้น (แบบเดียวกับ `coreRiskCfg`: บัญชีที่เปิดอยู่ = `state` · อื่น = `acctBooks[id]`)

## แก้
1. แทนการใช้ค่าคงที่ทุกจุดด้วย `satRiskCfg(accId)`:
   - `sat7dAcctBase` (~9396): `rpt = cnt.hi ? cfg.rptHi : cfg.rpt` + คืน `heatMax`, `newMax` ใน base
   - `sat7dCalc` (~9436) และจุดคู่กัน (~10634): `quotaFull` ใช้ `base.newMax` · `heatMax: base.heatMax`
   - แถบบัญชี Sat (~9969–9976): `heatBad` / ป้าย `x/{heatMax}%` · `newBad` / `x/{newMax}` · RPT แสดงค่าจริง
   - `STRIP_FIELDS.sat` suffix `/6%` `/2` → สร้างจากค่าตั้งของบัญชีตอนแสดง (ไม่ใช่สตริงตายตัว)
   - grep `SAT7D_RPT` `SAT7D_HEAT_MAX` `SAT7D_NEW_MAX` `/6%` `x/2` ให้ครบ · ค่าคงที่เดิมเปลี่ยนเป็น `SAT7D_RPT = 1.5, SAT7D_RPT_HI = 2` และใช้เป็น**ค่าเริ่มต้น**ของ `satRiskCfg` เท่านั้น
2. หน้าตั้งค่า (`openSettings` · แสดงเมื่อบัญชีเปิด port Sat · ตำแหน่งต่อจากส่วน "ความเสี่ยง Core") — ส่วนใหม่ **"ความเสี่ยง SAT — % ของถัง Sat"**:
   | ช่อง | id | ค่า | ตรวจ |
   |---|---|---|---|
   | เสี่ยงต่อไม้ (ปกติ) | `sSatRpt` | 1.5 | > 0 และ ≤ 5 |
   | เสี่ยงต่อไม้ (ผ่านเกณฑ์พิสูจน์ {N} ไม้ · avg R ≥ {R}) | `sSatRptHi` | 2 | ≥ ปกติ และ ≤ 5 |
   | ไม้ใหม่ต่อสัปดาห์ | `sSatNewMax` | 2 | จำนวนเต็ม 1–10 |
   - heat: บรรทัดเล็กใต้ส่วนนี้ "heat รวม Sat ตั้งที่ช่อง 'Sat — % ของถัง Sat' ด้านบน (ตอนนี้ {x}%)" — ไม่ทำช่องซ้ำ
   - ผิด = ข้อความแดงใต้ช่อง + ปุ่มบันทึกปิด (ทางเดียวกับช่อง Core เดิม `data-err-for`)
   - บันทึก → `settings.satRisk` ของบัญชีที่เปิดอยู่ · ป้ายหน่วยทุกช่องแบบช่อง Core
4. **ปิด MR (7E-4) ชั่วคราว — ไม่ลบโค้ด**
   - ตัวแปรเดียว `let SAT_MR_ENABLED = false;` (ใกล้ `SAT_MR_DIST_PCT` · เปิดผ่าน `window.SAT_MR_ENABLED` ได้ เพื่อให้เทส MR เดิมยังรันได้)
   - ปิด = ไม่มีปุ่มเพิ่มเงื่อนไข MR (`data-mr-add` ~10555) · `satV3MrAdd` กันไว้ (return ทันที) · ไม่มีคำแนะนำ/ข้อความชวนทำ MR ที่อื่น (grep `MR` `mrSide` `ui-mr-tag` ในส่วนสร้างแผน)
   - ข้อมูล MR เดิม (ถ้ามี): แสดง/ปิดไม้/Journal ได้เหมือนเดิม (ป้าย "MR · สวน Bias" · ตัวกรอง · เตือนถือเกิน 2 วัน) — ไม่ซ่อนข้อมูลที่มีอยู่ · ไม่ migrate
   - `Calc.mrSide` / `SAT_MR_*` / ฟังก์ชัน MR ทั้งหมด**คงไว้** · คอมเมนต์หัว `/* MR ปิดไว้ 1 ต.ค. 2569 — ผู้ใช้: 1 Bias · 1 ทิศ · 1 Setup · เปิดคืน = SAT_MR_ENABLED true */`
5. **ห้ามเทรดสวน Bias สัปดาห์ (ไม่มีทางลัด)**
   - ตอนนี้: แผนใหม่ใช้ Bias สัปดาห์อยู่แล้ว (`satV3NewPlan`) แต่ถ้า **Bias สัปดาห์สลับทีหลัง** แผนเดิมที่ทิศตรงข้ามยังส่ง order ได้ · ทาง 7D.2 เดิม (`sat7dCalc` · `flags.offBias`) แค่ติดนอกแผนแล้วยังกด "รวมด้วย (นอกแผน)" ได้
   - ใหม่: helper `satOffBias(idea)` = Bias สัปดาห์ปัจจุบันของ asset เป็น Long/Short และ ≠ ทิศของไม้ (`satV3SideOf(idea)` / `idea.bias`) → **ไม่ ready** ทุกบัญชี + เหตุผล `สวน Bias สัปดาห์ (ตอนนี้ {Long/Short}) — ยกเลิกแผนนี้ หรือรอ Bias กลับ` · **ไม่มีปุ่ม "รวมด้วย (นอกแผน)"** สำหรับเหตุผลนี้ (เหมือนที่ MR ไม่ผ่านกติกาไม่มีทางลัด ~10676/10875) · `satV3SaveOffplanAccount` / `satV3SaveSlot` กันซ้ำในโค้ดด้วย
   - ใช้ทั้งทาง V3 (`satV3PlanAcctCalc`) และ 7D.2 (`sat7dCalc`)
   - Bias สัปดาห์ยังไม่ตั้ง / Neutral = ไม่บล็อกด้วยเหตุผลนี้ (กติกาเดิมเรื่องไม่มี Bias ใช้ตามเดิม)
   - ไม้ที่เปิดอยู่แล้ว: ไม่บังคับปิด · แสดงป้ายเตือน `สวน Bias สัปดาห์` ที่การ์ดไม้/Positions (ไม่ใช่ป้าย MR)
   - **ไม่แตะ** ตัวคูณ ×0.6 เมื่อสวนทั้ง Macro และ Trend (`Calc.sizeRule`) — นั่นคือแผนตาม Bias แต่ภาพใหญ่ไม่เห็นด้วย ไม่ใช่สวน Bias
6. ไม้ที่เปิดอยู่แล้ว **ไม่คำนวณใหม่** (ขนาดไม้ที่บันทึกไปแล้วคงเดิม) · ค่าใหม่มีผลกับการ์ด/แผน Sat ที่ยังไม่ส่ง order
